# Gantt Timeline & Pricing

A lightweight tool that turns a plain YAML or JSON config into a polished, interactive HTML Gantt chart with live pricing tiers — no build step, no dependencies beyond Python and a browser.

![weeks-based output showing phase bars, summary cards, and tier tabs](https://placeholder)

---

## What it is

A single Python script (`gantt_generator.py`) reads your project config and injects it into a self-contained HTML template. The output is one file you can open in any browser, embed in a proposal, or drop into a Claude artifact — no server, no framework, no bundler.

The HTML itself is fully interactive: clicking a rate tier (Mid / Senior / Specialist, or whatever you define) instantly recalculates all costs without reloading.

---

## Purpose

Quoting a project takes time that should be spent doing the work. This tool is designed for developers, freelancers, and consultants who need to produce a professional timeline and pricing breakdown quickly — and update it just as quickly when the scope changes.

All the variables that change between projects live in one config file:

- Phase names, start/end positions, and effort hours
- Hourly rate tiers and their labels
- The time unit the project is measured in (weeks, days, or hours)

Change the config, re-run the script, and the HTML updates completely. No manual editing of HTML or JavaScript required.

---

## Reusability

The template (`timeline_and_pricing.html`) is designed to be reused across projects without modification. The generator script handles all substitution — phases, tiers, time unit, title — by replacing the `<script>` block at generation time.

**Adding a new project takes about two minutes:**

1. Copy `sample_config.yaml` (or `sample_config_days.json`)
2. Fill in your phases and rates
3. Run the generator

Because the config is a plain text file, it version-controls cleanly, diffs readably, and can be templated, scripted, or generated by another tool. The same config format works for weeks-based, days-based, and hours-based projects — only the `time_unit` field changes.

## Usage

### Requirements

- Python 3.9+
- PyYAML (for `.yaml`/`.yml` configs): `pip install pyyaml`

### Run

```bash
python gantt_generator.py my_project.yaml
# → my_project_gantt.html
```

```bash
python gantt_generator.py my_project.json --output proposal.html
```

### Config structure

```yaml
project_title: "LLM migration — 9-phase plan"
time_unit: weeks        # weeks | days | hours
active_tier: senior

phases:
  - name: "Discovery & assessment"
    start: 1
    end: 1
    hours: 8
  - name: "Infrastructure setup"
    start: 1
    end: 2
    hours: 20

tiers:
  mid:        { label: "Mid-level",      rate: 20 }
  senior:     { label: "Senior",         rate: 25 }
  specialist: { label: "LLM specialist", rate: 30 }
```

| Field | Required | Default | Notes |
|---|---|---|---|
| `project_title` | No | — | Updates the page `<h2>` heading |
| `time_unit` | No | `weeks` | `weeks` · `days` · `hours` |
| `active_tier` | No | first tier key | Must match a key in `tiers` |
| `phases[].name` | Yes | — | Label shown on the Gantt bar |
| `phases[].start` | Yes | — | First time unit the phase occupies |
| `phases[].end` | No | `start` | Last time unit (inclusive) |
| `phases[].hours` | Yes | — | Billable effort hours |
| `phases[].color` | No | auto palette | Hex colour for the bar |
| `tiers.<key>.rate` | Yes | — | Hourly rate in USD |
| `tiers.<key>.label` | No | key capitalised | Tab display name |
| `tiers.<key>.desc` | No | `$N/hr range` | Sub-label under the tab |

### Time unit behaviour

| `time_unit` | Gantt axis | Monthly cost card |
|---|---|---|
| `weeks` | W1, W3, W5 … | `total / (duration / 4.33)` |
| `days`  | D1, D6, D11 … | `total / (duration / 22)` |
| `hours` | H1, H9, H17 … | not shown |

`totalDuration` is calculated automatically as the maximum `end` across all phases.
